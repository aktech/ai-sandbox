Run AI coding agents in a box, not on your laptop.

One command gives every project its own Docker container with Claude Code and pi already installed. The agent sees only the folders you hand it. If something goes wrong, you delete the container and your machine is untouched.

Why

A coding agent running in your terminal can do anything you can. It can read your SSH keys, your cloud credentials and every .env file in your home directory, and one mistaken command reaches real files immediately.

Most of the time that is fine. The trouble is the one time it is not: a misread instruction, a prompt hidden in a web page the agent fetched, a cleanup step that deletes the wrong folder. There is no undo.

aisb draws a line around the agent. It keeps the speed of letting it work on its own, and limits the damage to one container you can throw away.

Agent on your machine

  • Sees your whole home directory
  • Can read keys, tokens and secrets
  • Installs tools into your setup
  • Mistakes land on real files

Agent in aisb

  • Sees only the folders you mount
  • Secrets stay out unless you add them
  • Tools live in the image
  • Worst case: aisb rm

How it works

Run aisb inside any project folder. The first time, it creates a container named after the folder. Every time after, it drops you back into that same container.

  1. One container per project.Each folder gets its own, so one project cannot see another.
  2. Only the folders you list.The project is mounted by default. Your git config, dotfiles or a shared library are added in one config file.
  3. Files stay yours.The container runs as a normal user with your user and group ids, so anything it writes is still editable from outside.
  4. Everything already installed.Debian slim with claude, pi, Node, Go, uv, pixi, git, tmux and zsh.

Commands

aisbEnter the sandbox for the current project.
aisb stopStop this project's container.
aisb rmDelete this project's container.
aisb lsList every sandbox.
aisb statusShow one container's status.
aisb buildBuild or rebuild the image.

Install

You need Docker running and Go to build the CLI. On macOS, colima works well. Building the image takes about five minutes, once.

Terminal 
# build the CLI and put it on your PATH
git clone https://github.com/aktech/ai-sandbox
cd ai-sandbox
make build
cp bin/aisb ~/.local/bin/

# build the image (one time)
aisb build

# sandbox any project
cd ~/dev/my-project
aisb

Configure

Mounts, memory, CPUs and published ports live in ~/.config/ai-sandbox/config.json. The default block applies to every project. A project entry adds its own mounts and sets its own memory, CPUs and ports.

config.json 
{
  "default": {
    "mounts": [
      "{{HOME}}/.gitconfig",
      "{{HOME}}/.claude/settings.json",
      "{{CWD}}"
    ]
  },
  "projects": {
    "/Users/me/dev/my-project": {
      "extra_mounts": ["~/dev/shared-lib"],
      "memory": "8g",
      "cpus": 4,
      "ports": ["3000:3000"]
    }
  }
}

Full reference, placeholders and environment overrides are in the README.
